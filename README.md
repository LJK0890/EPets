# EPets · 模组化电子宠物框架

主程序只做三件事：**加载模组（带依赖检查）、按 Id 调度内容、跑菜单循环**。
宠物、物品、特质、成就、剧情、随机事件、小游戏、NPC、术语、**菜单、配置** 全部由 DLL 模组在运行时注册，
`epet.exe` 里没有一条具体内容，也没有一个具体内容菜单项（只剩存档 / 读档 / 配置 / 退出 4 个系统菜单）。

| 指标       | 数值                                                                                                                                                     |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 模组       | 9 个（Core / Achievements / Story / Minigames / RandomEvents / Activities / Care / World / Debug）                                                       |
| 加载器接口 | 54 项（注册 4 + 名字库 3 + 数值背包 11 + 界面输入 11 + 成长时间规则 11 + 菜单调度 1 + 内容驱动 4 + 存档 2 + 实时输入 2 + 模式 1 + 配置 2 + 宠物定制 2）  |
| 内容总量   | 特质 20 · 物品 19 · 宠物 8 · 成就 17 · 剧情 20 · 事件 10 · 小游戏 22 · 术语 7 · NPC 5 · 菜单 35（模组）+ 4（宿主） · 配置 1（模组）+ 1（宿主） |
| 代码量     | 加载器 4227 行 · 模组 ~4846 行 · 宿主（shell）319 行 · 主程序 430 行                                                                                  |

## 快速开始

```bat
build.bat                 :: 产物：epet.exe、ModLoader.dll、mods\*.dll（项目根目录）
epet.exe                  :: 正常玩（菜单闭环）
epet.exe --demo           :: 无头自检：加载/依赖/剧情/事件/小游戏/存档/死亡全跑一遍
epet.exe --auto           :: 无头把每层菜单点一遍（冒烟；配置页只读）
```

`epet.exe` 静态链接 `ModLoader.lib`，运行时需要同目录的 `ModLoader.dll` 与 `mods\*.dll`；
工作目录必须是**项目根目录**（`pet.sav` / `dead.dat` / `ach.dat` / `config.dat` 也落在这里）。

启动时会打印模组加载摘要：成功几个、哪些因为缺依赖/接口版本/初始化失败/内容重名被跳过。
`--demo` 有错误时会额外打印条数；需要完整列表时可调用 `modloader_print_errors()`。

## 操作

| 键            | 作用                                       |
| ------------- | ------------------------------------------ |
| ↑ / ↓       | 菜单里上下选择                             |
| ← / →       | 菜单 / 对话翻页；滑动条配置项里减小 / 增大 |
| Z（或 Enter） | 确认 / 继续 / 选择当前项                   |
| X（或 Esc）   | 返回 / 取消 / 跳过对话                     |
| C             | 对话里有术语时查解释                       |

菜单选中项**不再用 `>` 箭头**，而是背景色 + 反色高亮（黑字青底；没有 ANSI 的控制台用
`SetConsoleTextAttribute` 等价实现）。数字 1~4 与 A/B 仅作为兼容保留。

## 容量模型

除编译期固定的 `KIND_COUNT`（内容种类数）外，所有表都按需动态扩容，计数类型统一 `uint64_t`：

| 数据                           | 上限                                                   |
| ------------------------------ | ------------------------------------------------------ |
| 宠物属性                       | `0~255`（`uint8_t` 上限）                          |
| 特质 / 背包槽位 / 单格物品数量 | `uint64_t`（指针 + 按 2 倍扩容）                     |
| 内容表（每种内容）             | `uint64_t`（动态数组）                               |
| 名字表（每种性别）             | `uint64_t`（动态数组）                               |
| 模组表 / 候选表 / 文件表       | `uint64_t`（动态数组）                               |
| 错误表 / 配置表                | `uint64_t`（动态数组）                               |
| 菜单标题文本                   | 短串 15 字节；长串 `0x0~0x7fffffff` + 动态 `char*` |
| 菜单每页项数                   | 配置滑动条 `1~16`（默认 4）                          |

实际上限由内存和地址空间决定，加载器不再用 `1024 / 256 / 64 / 128` 这类硬上限拒绝注册。

## 核心机制

**Id**：`typedef uint64_t Id`，运行时注册分配，每种内容各自从 1 编号；名字是持久化键，
`find(kind, name)` 反查。内容表 / 名字表 / 模组表都是 `uint64_t` 计数的动态数组，
注册时按 2 倍扩容，不再有固定槽位上限。

**位图**：`BitSet_t { uint64_t *words; uint64_t count; }`，成就/剧情状态存这里，条数不限，
按需扩容；由加载器分配，`modloader_pet_release()` 释放。

**宠物动态数组**：`Pet.traits` / `Pet.inv` 是 `uint64_t` 计数的指针数组，
`trait_cnt/trait_cap`、`inv_cnt/inv_cap` 按需扩容；`modloader_pet_release()` 释放。
背包删除会压缩数组，不再留下空槽。

**菜单文本**：`SelectOpt_t.text` 是 `Text_t`（16 字节带标记）：

- 短串：`tag = 0x80` + 15 字节定长串（含 NUL，最多 14 字节可见）；
- 长串：`uint64_t` 大端长度（`0x0-0x7fffffff`，首字节为 0）+ `char*` 动态数组。
  模组用 `g_api->opt_text(&opts[i], fmt, ...)` 写文本；`ui_menu` 显示完会自动释放。
  `ui_option(text, selected)` 给自定义列表复用同款高亮。

**统一文字引擎**：剧情页、对话、随机事件、`ui_print` 共用一套解析器，支持 `§` 控制码（UTF-8 的 `§` 是 `C2 A7`）。
`ui_print` 现在也会解析 `§` / `{pet}` / `⌈术语⌋`，没有这些标记的纯文本照旧原样输出：

| 控制码  | 作用                                                     |
| ------- | -------------------------------------------------------- |
| `§S` | 启用流式输出（每字符约 15ms；无头模式不等待）            |
| `§T` | 启用术语标识（绿色；按 C 查术语）                        |
| `§O` | 启用讲述人标识（黄色）                                   |
| `§0` | 清除所有格式（流式 / 术语 / 讲述人 / 颜色）              |
| `§P` | 替换为宠物名（蓝色）                                     |
| `§C` | 立即清屏并继续输出；这一屏不能 ← 回来，但不影响更早的页 |
| `§F` | 立即切到下一屏并继续输出；这一屏可以 ← 回来             |

例如：

```text
§ONPC1§0：§S你好啊！§0
§S这听起来很中二§0§C§S这听起来很酷§0
```

`§C` / `§F` 在解析到时就**立即执行，不需要按 Z 或 →**：当前屏渲染完会清屏并继续输出下一段。
它们可以写在**要离开的那一屏末尾**，也可以写在下一屏开头；写在数组页末尾时，下一个数组页也会直接进入。

- `页1 页2[§C] 页3`：显示页1、页2后自动清屏到页3；从页3按 ← 跳过页2回到页1（回到页1后按 → 也跳过已清除的页2）；
- `页1 页2[§F] 页3`：显示页1、页2后自动切到页3；从页3按 ← 回到页2，再回到页1；
- 普通数组页之间仍由玩家用 Z/→ 切换；数组页默认可回退，`§F` 让自动切出来的屏也进入回退历史，`§C` 不进入。

旧语法继续可用：`{pet}` 替换为宠物名（蓝色），`⌈术语⌋` 绿色高亮并参与 C 键查询。
颜色只在启用 VT 的控制台输出；重定向到文件时只保留纯文本。

**跨内容引用**：一律用名字（成就奖励写物品名、剧情分支写 NPC 名、小游戏写宠物类型名、
子菜单写父菜单名、依赖写“模组:种类/名字”），加载器运行时解析。

**菜单也是内容**：`Menu_t` 声明“名字 / 显示文字 / 父菜单 / 排序 / 标志 / 回调”，
宿主只调用 `menu_run(pet, NULL)`。菜单项可以来自任意模组，嵌套关系只看 `parent` 名字。
每页项数由滑动条配置 `ui.page_size` 决定（1~16，默认 4）；选中项用背景色 + 反色高亮。
宿主自己注册 4 个系统菜单：存档 / 读档 / 配置 / 退出。

**配置也是内容**：`Config_t` 声明“持久化键 / 显示名 / 说明 / 类型 / 默认值 / 范围”。
类型有 `CFG_BOOL`（开关）、`CFG_INT`（短列表）、`CFG_SLIDER`（滑动条 `< value >`，←/→ 调整）。
配置页把当前已注册的配置项列出来；改动立即写 `config.dat`（整块异或 + 校验字节）。
模组用 `config_get/config_set` 读写；宿主自带 `ui.page_size`，Care 自带
`care.feed_trait_special`。配置表同样是动态数组。

**依赖与诊断**：`ModInfo_t.requires` 的每一项可以是：

- `"Core"`：只要求模组 Core 加载成功；
- `"Core:物品/粗粮"`：还要求 Core **本人**注册了物品“粗粮”；
- `"Story:剧情/首次商场"`、`"Achievements:成就/铁石心肠"` 同理，支持
  特质/物品/宠物类型/成就/剧情/事件/小游戏/术语/NPC/菜单/配置。

加载分两阶段：先 `LoadLibrary + mod_info` 做静态校验，再按依赖多轮扫描；依赖模块初始化完成后
再校验它是否真的注册了指定内容。失败原因会进动态错误表并打印：缺少依赖、依赖失败/循环、
依赖格式错误、依赖种类未知、依赖内容缺失、依赖内容不属于该模组、接口版本不符、
`mod_init` 返回 0（带 `mod_error()`）、DLL 加载失败、模组重名、内容重名（警告）。

**喂食特质特判**：`Care` 的喂食菜单在调用物品效果后按**特质名字**检查：

- 贪吃：食物带来的心情下降归零；
- 挑食：吃食物额外心情 -5。

可在配置页关闭 `care.feed_trait_special`。依赖用 `Core:特质/贪吃` / `Core:特质/挑食`
声明，避免特质改名后静默失效。

**控制台**：主菜单的「控制台」取代原来的调试选项，直接输入命令：

```text
help / ?                 命令帮助
pet / bag                宠物摘要 / 背包列表
coins [n]               加鲁尼（默认 1000）
exp [n]                 加经验（默认 500）
full                    五维全满（255）
stat <名字> [值]        查看/设置属性（hunger clean happy health energy）
heal                    清除疾病
age [n] / level [n]     查看/设置年龄、等级
sleep / rebel           切换睡眠、叛逆
item <名字|Id> [数量]   添加物品（list items 可查名字和 Id）
itemid <Id> [数量]      按 Id 添加物品
randitem [数量]         随机有价物品（默认 5）
trait <名字|Id>         添加特质（不检查互斥）
list [种类]             列出内容，默认 items
find <种类> <名字>      按名字查 Id
config <名字> [值]      读取/设置配置
story <场景>            播放剧情（mall/hospital/...）
ach                     轮询成就
save / clear / quit     存档 / 清屏 / 退出
```

输入用行编辑：Backspace 删除，Enter 执行，Esc 或 `quit` 退出；改动命令会自动存档。
`--demo/--auto` 下不读键盘，控制台跑内置脚本（help → 加钱/经验 → 满属性 → 物品 → list → ach → save → quit）。

**实时输入**：`key_poll()` 非阻塞读键、`now_ms()` 毫秒时钟，雪球大战（5 秒）、力量比拼（4 秒）、
火焰烧烤（0~6 秒火候窗口）都是真·限时，轮询间隔与原版一致（100ms 一拍）。

**场景标签**（剧情触发点）：

`adopt` 领养 · `work` 差事 · `work_apply` 应聘 · `travel` 旅游 · `mall` 商场 · `hospital` 医院 ·
`amuse` 游乐园 · `park` 公园 · `spa` 洗浴 · `battle` 比试 · `center` 桥屋 · `idle` 日常结算 · `death` 离世

**存档**（四个文件，都是「整块异或 0x5A + 末尾校验字节」）：

| 文件           | 内容                                                                   | 写入时机           |
| -------------- | ---------------------------------------------------------------------- | ------------------ |
| `pet.sav`    | 当前宠物：类型/名字/动态特质数组/动态背包/成就/剧情（`PET_VER = 3`） | 关键操作后、退出时 |
| `dead.dat`   | 最近 5 条逝去记录（`DeadPet_t` 快照）                                | 每次离世 / 清空    |
| `ach.dat`    | 跨存档成就（位图计数为 uint64，格式版本 2）                            | 每次解锁成就       |
| `config.dat` | 配置值（name → int32，动态条数，格式版本 3）                          | 每次配置改动       |

**生死与重生**：`modloader_pet_day()` 逐日结算（衰减/成长/生病/寿终），健康归零时：

1. 立即置 `dead` / 死因并写 `pet.sav`（**死亡状态持久化**，关掉进程也不会丢）；
2. 播 `death` 场景剧情、离世画面，写 `dead.dat` 记录并轮询成就。

**首次进入游戏**（没有存档）：宠物类型、性别、名字、2 个特质（1 正 1 负）全部随机，不收钱。

**第一只离世后**（同一进程或下次启动读到 `dead` 时）进入「新的伴兽」向导，费用从继承的鲁尼里扣：

| 项目       | 随机                     | 自选                 |
| ---------- | ------------------------ | -------------------- |
| 类型与性别 | 免费                     | 1000                 |
| 名字       | 免费（性别名字库）       | 1000（从名字库里挑） |
| 特质       | 前 2 个免费；之后 500/个 | 1000/个              |

**桥屋 → 祭坛**（游戏进行中随时可用，见 Activities 模组）：

| 项目         | 随机   | 自选    |
| ------------ | ------ | ------- |
| 名字（重设） | 500    | 1000    |
| 特质（追加） | 500/个 | 1000/个 |
| 特质（删除） | —     | 2000/个 |

新宠物继承死亡宠物剩余的鲁尼，带初始属性、新手礼包和 `lost_friend`
（触发「旧友的信」）；死亡后的重生不再重复首次领养剧情。

## 已知限制

- 依赖只按**模组名 + 内容名**匹配，不带版本约束；内容名区分大小写，模组名不区分。
- 依赖成环时相关模组全部拒绝加载；依赖内容必须由声明里写的那个模组注册。
- 内容/名字/模组/配置表的上限是 `uint64_t`，但实际受内存限制；扩容失败会报“内存不足”。
- 菜单文本短串最多 14 字节可见；长串上限 `0x7fffffff` 字节。`ui_menu` 会释放选项文本，
  调用方仍需释放自己的 `SelectOpt_t` 数组。
- 存档格式升到 `PET_VER = 3`（动态数组、uint64 计数、uint64 字符串长度）；旧存档不兼容，没有迁移。
  `dead.dat` 版本 2、`ach.dat` 版本 2、`config.dat` 版本 3。
- 菜单每页 1~16 项（滑动条配置）。
- `--auto` 每层只点第一个菜单项（冒烟用），配置页只读；实时小游戏在无头模式下用虚拟时间快进。
